How does a screenshot frame tool work

I am describing the catalog’s model here, not reverse-engineering Shots.so. You take a bitmap, sit it on a background, and write a new bitmap at a known size.

The prompt names three end-to-end journeys. Tonight you need the first one.

Drop a screenshot on the canvas. Pick a gradient. Adjust padding and corner radius. Export a social-ready PNG.

The screens the prompt asks for are a canvas, a style panel, an export bar, and presets. For 2 hours you can live with the first three. Presets belong to the 6-hour row.

The canvas is a drop target, a framed shot, and sliders that repaint live. The style panel is swatches, padding, radius, shadow, and a frame picker. The export bar is size presets, a PNG download, and copy-to-clipboard.

The data model on the page is local Composition, StylePreset, and ExportJob objects only. Tonight those can be one object.

The capability line is Astro, Alpine, and browser APIs. This site is an Astro app on Cloudflare, so that is the path I default to. Use Rails if that is your weekday language.

Paste from the clipboard, then reject the rest

The fastest path is the screenshot key, then paste. Agents hide that behind a file picker because a picker is easier to demo.

The mini-prompt on the page is “Paste, drop, or reject”. Listen for paste events. Pull image data from clipboard items. Keep drag-and-drop as the second route, with a visible drop target during dragover. A file picker is the fallback.

Validate by decoding, not by trusting extensions or MIME strings. Accept PNG, JPEG, and WebP that decode into an image. Reject a PDF or a corrupt dump with an inline message, and leave the current composition untouched.

async function acceptShot(file) {
  try {
    return await createImageBitmap(file)
  } catch {
    throw new Error('Drop a PNG, JPEG, or WebP. The current frame is unchanged.')
  }
}

A new valid image replaces the screenshot and keeps the current style settings, so the next paste reuses the look.

Cap input dimensions. The prompt wants a 6K capture downscaled with a notice, so the tab does not stall. Tonight, refuse anything huge with a sentence on the canvas.

Never send image bytes to a server or to analytics. The guardrail on the page is explicit: render and export entirely in the browser so screenshots never leave the device.

Fit the screenshot without upscaling

A tall phone shot and a wide desktop shot both have to sit in a 1600 by 900 preset. Agents scale the preview by CSS and call it done. The export then either crops the shadow or smears the text.

The mini-prompt is “The layout solver behind the pretty padding”. Given output dimensions and a padding percentage, scale the screenshot to the largest size that fits the padded box, keep the aspect ratio, and center it. Cap at natural size so a small window capture stays sharp, and let the background own the extra room.

function fitScreenshot(shot, box) {
  const scale = Math.min(
    box.width / shot.width,
    box.height / shot.height,
    1
  )
  const width = Math.round(shot.width * scale)
  const height = Math.round(shot.height * scale)
  return {
    width,
    height,
    x: Math.round((box.width - width) / 2),
    y: Math.round((box.height - height) / 2),
  }
}

const box = { width: 1216, height: 684 }
fitScreenshot({ width: 2400, height: 1350 }, box)
//{ width: 1216, height: 684, x: 0, y: 0 }

That 1216 by 684 box is a 1600 by 900 preset with 12 percent padding on each side. A 2400 by 1350 hero fills it. A 800 by 500 window capture stays 800 by 500 and sits in the middle.

Layer order matters. Background, then shadow, then the frame, then the screenshot clipped to the corner radius. When a frame is present, put the radius on the frame’s outer edge so the screenshot’s own corners stay square inside it.

The frame’s header bar adds height. The fit has to account for that, or a tall shot overflows the padded box. Recompute the layout on every slider change and every preset switch.

Export at exact pixel dimensions

The preview canvas is sized for the viewport and scaled by device pixel ratio. Its bitmap is almost never 1600 by 900.

The mini-prompt is “Export at exactly 1600 by 900”. On export, create an offscreen canvas at the preset size and paint the composition again. Every measurement is computed for the target size. Do not scale the preview up.

async function exportPng(composition) {
  const canvas = document.createElement('canvas')
  canvas.width = composition.preset.width
  canvas.height = composition.preset.height
  paintComposition(canvas.getContext('2d'), composition)

  const blob = await new Promise((resolve, reject) => {
    canvas.toBlob((result) => {
      if (!result) {
        reject(new Error('Could not encode the PNG'))
        return
      }
      resolve(result)
    }, 'image/png')
  })

  return blob
}

paintComposition is the same function the live preview calls, with the preset width and height instead of the viewport box. Corner-radius clipping should antialias. Shadows should land inside the bounds. Use a high-quality resample when the screenshot shrinks.

Offer a PNG download and a copy-to-clipboard from that blob. Where the clipboard API refuses images, show a fallback message and keep the download.

The prompt’s done state is a file that measures exactly 1600 by 900, regardless of window size or display density. Open it and read the pixels.

function outputName(filename) {
  const dot = filename.lastIndexOf('.')
  const stem = dot === -1 ? filename : filename.slice(0, dot)
  return `${stem}.shot.png`
}

outputName('hero-home.png')
//'hero-home.shot.png'

What not to build in a Shots.so clone

Leave out accounts, cloud storage, a template marketplace, video mockups, and team libraries.

The non-goal on the page already names those. You are replacing the frame you currently rent for tweets.

If the agent starts an upload to R2 “so the composition survives a refresh”, stop it. Paste the non-goal again. Refreshing discards local work, and that is the product.

The 6-hour row, after you post one

Use the tool as the real framer for a week. Then look at the second estimate.

Style presets, so the next shot matches the last one. Batch export. Arrows and a caption. A few social sizes beyond the first preset.

The preset mini-prompt is “Style presets that live in localStorage”. Save background, padding, radius, shadow, and frame under a name. Store a small thumbnail as a data URL, capped, because quota is finite. Version the schema so an old preset loads with defaults for a new field instead of crashing.

const preset = {
  version: 1,
  name: 'Launch lime',
  padding: 0.12,
  radius: 18,
  shadow: 0.35,
  frame: 'browser-light',
  background: {
    type: 'gradient',
    from: '#c8ff45',
    to: '#7bc8ff',
  },
}

Applying a preset changes style settings and never touches the loaded screenshot. Include rename, delete with a confirm, and a reset-to-defaults control. Persist last-used settings across sessions. Treat corrupt JSON as defaults.

The catalog says 6 hours for that row. Stop there.
