What you get when you build your own with ezvibecode Typeform

The Typeform page splits the work into three rows.

The first row is the one you want tonight. One question at a time. A response table. A public share URL and an inbox of answers.

The second row is 6 hours. Logic jumps, theming, a proper CSV export, webhooks. Those can wait until someone has submitted.

The third row is 2 weeks and up. A visual builder, payment fields, an integrations gallery. The table labels that row as the part you should skip.

If you tell an agent to “clone Typeform”, it aims at the third row. Use the prompt on the page. It is written for a useful v1, and you still have to keep it on the first row.

The estimate table puts a polished CSV on the 6-hour row. I would still download the current table tonight. Without an export you are looking at answers in a browser tab you do not own.

Read the non-goals before you copy anything

Open the guide. Read the audience and the non-goals before you touch the prompt.

The non-goal is the useful sentence: do not create a general visual workflow builder or payment fields.

The guardrail sits next to it. Validate and rate-limit submissions server-side. Include a honeypot field. A public form that writes to your inbox will get hit by bots. You deal with that on the server, not with a hidden CSS trick the crawler ignores.

Then pick the stack you already write. Every prompt ships in four flavors: AHA (Astro, HTMX, Alpine.js), Next.js, Laravel, and Rails. The AHA version for this product uses Astro, HTMX, and D1. This site is an Astro app on Cloudflare, so that is the path I default to. Use Laravel if that is your weekday language. The scope matters more than the framework.

Copy the prompt. Before you run it, add one extra line at the top: ship the 2-hour row only. One-question flow, response table, a CSV download. Stop.

Walk the first Typeform journey

You create a form from scratch. You add four questions. You mark email required. You preview it on a phone-sized width. You publish a stable share URL.

A respondent opens that URL. They see one question. They go next. They get a validation message if the email is garbage. They land on your thank-you sentence.

You get a notification. You open the table. You search for the email. You export the current rows.

Keep that share URL stable when you edit a question later, so the link in your newsletter and the link on the booking page keep working.

The screens the prompt asks for are a forms list, a builder, a public responder, and a results view. For 2 hours, a short question list is enough. Type, label, required, options. The ordered rail, theme controls, and logic summary can wait.

The public responder is what the visitor sees. One focused question per view, a progress mark, back and next, and validation that keeps the answer they already typed.

The results view is what you see. A table, a detail page, and a download. Webhook-delivery status can wait.

The data model on the page is Form, Question, LogicRule, Submission, Answer. Tonight you need Form, Question, Submission, and Answer. LogicRule waits.

One more rule from the prompt, and it is a good one. Published forms use an immutable version so editing cannot corrupt historical answers. If 2 hours are real, freeze the published questions as a JSON snapshot on the form row. Do not invent a versioning UI. Just stop live-editing questions someone already answered.

Code the public POST yourself

Agents will give you a pretty form and a wide-open POST endpoint. The catalog already tells you to validate and rate-limit on the server, and to include a honeypot.

The honeypot is a field humans never see. Bots fill it. You drop those submissions without a lecture.

function shouldAccept({ honeypot, submissionsLastHour }) {
  if (honeypot.trim() !== '') {
    return { ok: false, reason: 'ignored' }
  }

  if (submissionsLastHour >= 20) {
    return { ok: false, reason: 'rate-limited' }
  }

  return { ok: true }
}

shouldAccept({ honeypot: 'buy followers', submissionsLastHour: 3 })
//{ ok: false, reason: 'ignored' }

Twenty an hour per form is where I would start. High enough for a launch day. Low enough that a script cannot fill the table. Tell the human you are rate-limited. A bot can get the thank-you screen and no row.

Required email is the other check that has to live on the server. The prompt scenario is specific: reject malformed input, keep the answer, focus the field explanation. Do not wipe the rest of the session because question two is missing an @.

The mini-prompt on the page is “The CSV export that can’t attack a spreadsheet”. Respondents type =HYPERLINK into a feedback box. Spreadsheet apps will run that as a formula if you let them.

function escapeCsvCell(value) {
  let text = String(value)
  if (/^[=+\-@\t\r]/.test(text)) {
    text = `'${text}`
  }
  if (/[",\n\r]/.test(text)) {
    text = `"${text.replaceAll('"', '""')}"`
  }
  return text
}

escapeCsvCell('=2+2')
//'=2+2

Prefix a leading =, +, -, or @ with a single quote so the cell stays text. Quote fields that contain commas, quotes, or newlines. Double embedded quotes. End rows with CRLF. Put a UTF-8 BOM at the top of the file so Excel does not mangle accented names.

Columns: one per question in form order, plus submitted-at and submission id. Name the file with the form slug and the export date, studio-intake-2026-10-11.csv.

That is enough for tonight. Streaming 50,000 rows is the 6-hour version of the same download.

What not to build in a Typeform clone

Leave out the visual builder, payment fields, and anything that looks like an integrations gallery.

Logic jumps are on the feature list. Skip them until a real form needs “if they said newsletter, skip the site questions”. Theming is two CSS variables and a logo if you have ten extra minutes.

If the agent starts a template marketplace, stop it. Paste the non-goal again.

The 6-hour row, after someone submits

Use the form as the real intake for a week. Then look at the second estimate.

Logic jumps. Each rule says: if question X matches, jump to question Y or end. The mini-prompt is “Logic jumps that can’t loop forever”. Jumps go forward or end. Record the path they took, so a required question they were allowed to skip does not block submit.

Theming, so the form looks like the rest of your site.

A webhook, so a submission can hit the tool you already use. The mini-prompt is “One click, one submission, even on hotel wifi”. Issue a token when the form loads. One token, one row. Fire the email and the webhook after the insert commits.

Immutable versions, if you edit questions after people have answered. The mini-prompt is “Edit the form without gaslighting old answers”. Publishing freezes the questions. Old rows keep the wording they saw.

That is the solid v1. The catalog says 6 hours. Stop there.
