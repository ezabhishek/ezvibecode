Walk the first DocSend journey

You upload series-a-deck.pdf. The app confirms 14 pages and the title. You add a small logo in the viewer header. You create two share links, one named Acme and one named Northwind, each with its own slug.

A prospect opens the Acme URL. They type an email to get in. A viewer session starts. They read a few pages in the browser, leave, and later resume through the same link.

You look at the two links. Acme has an open. Northwind does not. You copy the Acme URL again, or you revoke it if that thread died.

The screens the prompt asks for are a document library, link settings, a secure PDF viewer, and an analytics page. For 4 hours you need the library, one link form, and the viewer. The library is title, page count, active-link count, recent opens. The form is link name, email gate, copy URL, revoke. The viewer is a branded header, pages, and no public file URL in the address bar. A page-by-page timeline waits.

The data model on the page is Document, ShareLink, ViewerSession, PageView. Tonight you need the first three. A single open event is enough. PageView is the 2-day row.

Code the viewer so the file URL never leaks

Agents will upload the PDF to a public bucket and drop the object URL into an iframe, which is a download with extra CSS. Anyone with the network tab has the file forever, even after you revoke the link.

The mini-prompt on the page is “The PDF viewer that never leaks the file URL”. Store the original in private object storage. The viewer asks for one page, or one byte range, at a time. The endpoint checks two things on every request: the share link is still active, and this caller holds a valid session for that link. If both pass, mint a signed delivery URL that expires in about 60 seconds. Never mint a grant for the whole file.

A link revoked mid-session must fail the next page request, not only future sessions. A grant is scoped to one document, so a leaked URL cannot fetch a sibling deck.

async function grantPage(db, { linkId, sessionId, page }) {
  const session = await db.getSession(sessionId)
  const link = await db.getLink(linkId)

  if (!session || session.linkId !== linkId) return null
  if (link.revokedAt) return null

  return signDelivery({
    storageKey: `docs/${link.documentId}/original.pdf`,
    page,
    expiresInSeconds: 60,
  })
}

await grantPage(db, {
  linkId: 'lnk-acme',
  sessionId: 'ses-19',
  page: 3,
})

Paste any of those signed URLs into a private window after the TTL. It should fail. Revoke lnk-acme and the next page turn should fail too, even if the tab was already open. The original object is never publicly addressable.

The email gate is claimed identity

Tonight a gate can be an email field. Passcodes wait for the 2-day row. The email is what the visitor typed, not a verified inbox. Trim and lowercase it so [email protected] and [email protected] are one claim on the session.

The mini-prompt for later passcode work is “The passcode gate that fails without leaking”. Steal one rule from it tonight. A revoked link must not create a session, and the error page must not expose the document title, the owner, or the company branding. A dead link and a missing email return the same generic message.

async function openGate(db, { slug, email }) {
  const link = await db.getLinkBySlug(slug)
  const generic = 'This link is unavailable.'

  if (!link || link.revokedAt) {
    return { ok: false, error: generic }
  }

  const session = await db.createSession({
    linkId: link.id,
    claimedEmail: email.trim().toLowerCase(),
    startedAt: new Date().toISOString(),
  })

  await db.incrementOpens(link.id)
  return { ok: true, sessionId: session.id }
}

await openGate(db, {
  slug: 'acme-deck',
  email: '[email protected]',
})

Rate-limit attempts per link even without a passcode, so a bot cannot farm sessions. Hash passcodes later. The database should never contain a plaintext one.

Two links, two counters

The first journey creates separate share links for two prospects. Do that at 4 hours if you send the same deck twice. Each link gets an immutable identifier. Revoking Acme blocks new sessions on Acme. Northwind keeps working. The two counters never share a row.

The mini-prompt is “Revoke one link, keep the receipts”. Historical opens stay attached to the identifier you revoked. Duplicating a link copies the gate settings into a fresh identifier with zero opens, so you can rotate a URL that leaked in Slack without retyping the form.

async function revokeLink(db, linkId) {
  await db.setRevokedAt(linkId, new Date().toISOString())
  await db.invalidateGrants(linkId)
}

await revokeLink(db, 'lnk-acme')

Invalidate grants in the same write. If you mark the row revoked and leave old signatures valid for 60 seconds, a tab that already loaded page 1 can still walk the rest of the deck.

What not to build in a DocSend clone

Leave out e-signatures, a data room with folders, CRM sync, and anything that looks like a per-slide heatmap.

Passcodes are on the feature list. Skip them until the email gate has been used by a real prospect. Expiry waits. CSV waits. Page-by-page duration waits.

If the agent starts a Salesforce connector or a signing ceremony, stop it. Paste the non-goal again. CRM sync belongs on HubSpot CRM, $20–$150 a person a month, about 4 days.

The 2-day row, after you have sent a deck

Use the viewer as the real tool for a week. Then look at the second estimate.

Passcodes, hashed, with the fail-closed error page from the mini-prompt. Five rapid wrong attempts trip a rate limit. A correct passcode on an expired link still yields no session and no metadata.

Expiry is an absolute timestamp. Check it on the gate and on every grant. A session that started before expiry does not get new pages after the clock passes.

Page-level reading analytics. The mini-prompt is “Read-time analytics from a tab you can’t trust”. The client emits page turns, visibility changes, focus and blur. A page accumulates time only while it is the current page and the tab is visible. If no event arrives for 60 seconds, stop attributing time, so a tab left open overnight does not record nine hours on page 3. Pages 1, 2, and 5 should show exactly that sequence. A repeat visit to page 1 is a second entry, not a merge. Label every number approximate. Never fingerprint the device.

function pageSeconds(events, idleCutoff = 60) {
  const visits = []

  for (let i = 0; i < events.length; i++) {
    const current = events[i]
    if (current.type !== 'page') continue

    const next = events[i + 1]
    const end = next ? next.at : current.at + idleCutoff * 1000
    let seconds = (end - current.at) / 1000
    if (!current.visible) seconds = 0
    if (seconds > idleCutoff) seconds = idleCutoff

    visits.push({ page: current.page, seconds })
  }

  return visits
}

const events = [
  { type: 'page', page: 1, at: 0, visible: true },
  { type: 'page', page: 2, at: 12000, visible: true },
  { type: 'page', page: 5, at: 40000, visible: true },
  { type: 'hide', at: 55000 },
]

pageSeconds(events)
//[{ page: 1, seconds: 12 }, { page: 2, seconds: 28 }, { page: 5, seconds: 15 }]

Totals across pages must not exceed wall-clock session length. If they do, your idle cutoff is not firing.

CSV export of that timeline, filtered by link. Escape spreadsheet formulas on the way out.
